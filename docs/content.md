# Bundled content

Everything the client ships under `apps/client/public/content` is either
generated from a recorded source or authored in this repository. The content
profile in `apps/client/config/contentProfile.mjs` lists every file, and
`apps/client/config/contentManifest.test.mjs` pins the set and its digest.

| Directory | What it is | How it is produced |
|---|---|---|
| `content/core` | The core rules baseline every edition shares: levels and experience, ability score increases, alignments, sizes, vision, damage types, conditions, languages, proficiency lists (armor, weapons, skills, saving throws, tools), weapon and armor properties, and the internal grants, options and multiclassing scaffolding. | Authored here (see below); `packages/engine/src/content/core-baseline.test.ts` checks every identifier in `core-required-ids.json` stays defined. |
| `content/srd-5.1` | The System Reference Document 5.1 subset (2014 rules), including the companion and familiar stat blocks the 2014 features select from. | Generated by `scripts/build-srd-content.mjs build --edition 5.1` from the vendored corpus, sliced by `third-party/srd-5.1/srd-5.1.map.json`; `ranger-favored-terrains.xml` is authored. |
| `content/srd-5.2.1` | The System Reference Document 5.2.1 subset (2024 rules). | Generated by `scripts/build-srd-content.mjs build --edition 5.2` from the vendored corpus, sliced by `third-party/srd-5.2/srd-5.2.1.map.json`; `source.xml`, `skill-supports.xml` and `skill-expertise.xml` are authored. |
| `content/system` | System elements the engine supplies itself (element identities, proxies, unarmed-strike riders). | Authored here; bundled through the content manifest as `system/…`. |

`npm run content:check-srd` rebuilds both SRD subsets in memory and fails on
any drift from the committed files, so the committed output is always the
generator's.

## The core baseline

The core files encode the rules scaffolding the engine walks: which level
grants which proficiency bonus, which internal grants a character starts with,
which skill keys off which ability, which weapons a proficiency covers. Their
element identifiers are the ones saved characters and uploaded content refer
to, so they never change; `core-required-ids.json` is the list.

Rules text in these files is drawn from the System Reference Documents (used
under their licences, see `NOTICE.md`); the remaining wording is this
project's own. The files carry no comments or empty blocks, and the
publication audit (`npm run audit:public`) checks them along with the rest of
the tree.

## The corpus

The generated subsets are sliced from the public elements corpus recorded in
`third-party/elements/provenance.md`. It is fetched at a pinned commit and
byte-verified (`npm run corpus:fetch`), never committed, and nothing outside
the reviewed maps ever reaches the bundle. Users may upload further content
themselves; the engine treats it exactly like the bundled files.
